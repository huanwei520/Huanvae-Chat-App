# 经验回顾与 Skill 自更新

任务完成（自检 + 盲审通过）后自动执行。目标：将本次踩坑经验和重复模式固化到 skill/rule 文件中，避免未来重复犯错和浪费 token。

## 第 1 步：快速回顾（无料则跳过）

回顾本次任务执行过程，检查以下两类信号：

### A. 踩坑点（浪费 token 的错误/重试）

- 编译错误反复出现同一类问题（类型链调用错误、import 遗漏、生命周期问题等）
- API/库用法搞错导致多次修改（如 Result 没有 .filter()、某 crate 版本 API 变动）
- 配置/环境问题反复排查（环境变量名拼错、路径不对、容器端口搞混）
- 测试编写时踩的坑（ApiResponse 解包、边界值不匹配验证规则、测试数据硬编码）
- 文档/注释与代码不一致导致误判

### B. 重复模式（每次都手动执行的相同步骤）

- 固定的检查步骤序列（每次都要查某个配置、每次都要确认某个前置条件）
- 每次都要查的配置/文件路径
- 重复的代码模式/模板（每个新端点都要写的样板代码）
- 重复的排查路径（每次某类错误都要查同样的地方）

### 快速退出

如果本次任务执行顺利，没有明显踩坑或重复模式：

> 「本次无可归纳经验，跳过 skill-evolve。」

输出上面一行后**立即结束**，不做空分析。

---

## 第 2 步：归纳经验条目

对识别到的每个踩坑点/重复模式，归纳为结构化经验条目：

```
- **经验**: [一句话描述规则]
- **Why**: [为什么会踩坑 / 为什么需要自动化]
- **场景**: [在什么条件下触发]
- **归属模块**: [对应哪个模块/skill/rule，或「通用」]
```

示例：

```
- **经验**: sqlx 0.8 的 query_as 需要显式生命周期标注
- **Why**: 0.7 → 0.8 API breaking change
- **场景**: 使用 sqlx query_as 构建查询时
- **归属模块**: common
```

---

## 第 3 步：定位目标文件

对每条经验，按以下优先级搜索目标文件：

1. **关键词搜索** — `grep` 经验关键词在 `.claude/skills/` 和 `.claude/rules/` 中搜索，看是否已有相关规则
2. **按归属模块匹配**：
   - 模块专属经验 → `.claude/rules/<模块名>.md`
   - 某类任务流程经验 → `.claude/skills/<对应skill>/SKILL.md`
   - 通用编码/架构经验 → `.claude/rules/common.md`
3. **无匹配** → 进入第 4 步的创建流程

**去重检查**：读取目标文件，确认没有已存在的相同或近似规则。如果已有，跳过该条。

---

## 第 4 步：更新或创建

### 更新已有文件

- 读取目标文件，找到合适的插入位置（同类规则附近）
- 追加经验条目，保持文件原有格式和风格
- rule 文件追加到「注意事项」或「已知问题」章节
- skill 文件追加到相关流程步骤的注意事项中

### 创建新文件

仅当经验不属于任何已有文件时，按以下决策树决定形式：

```
该经验是否几乎每次任务都会用到？
├─ 是 → 写入 CLAUDE.md（仅一行调取指令或简短规则）
└─ 否 → 该经验是否构成完整的可复用流程？
    ├─ 是 → 独立 skill（.claude/skills/<name>/SKILL.md）
    └─ 否 → 该经验属于哪个模块？
        ├─ 有对应模块 → 更新 .claude/rules/<模块名>.md
        └─ 通用 → 更新 .claude/rules/common.md
```

### 同步 memory

如果经验属于 feedback 类型（用户纠正或确认的非显而易见做法），**同时写入 memory 系统**的 feedback 文件，确保跨会话持久化。判断标准：

- 该经验是用户明确纠正的 → 写 memory
- 该经验是 AI 自己发现的编码技巧 → 仅写 skill/rule，不写 memory
- 该经验涉及项目特殊约定（非代码可推导） → 写 memory

### 输出变更摘要

```
### skill-evolve 变更摘要

| 操作 | 文件 | 变更内容 |
|------|------|----------|
| 更新 | `.claude/rules/xxx.md` | 追加：xxx 规则 |
| 新增 | `memory/feedback_xxx.md` | 记录：xxx 经验 |
```

## 沉淀层（update 步）交付纪律 — 三问必答、不沉淀立据、穷举/点名声明（块 `1788301655770-1` update REJECT 实证）

update/沉淀步交付若只有「经验叙述 + 建议」（未实际修改任何 skill/rule 文件）会被判官直接打回。四条硬要求：

1. **落地优先**：skill/rule 增补要**实际写入文件**（本 skill 即授权并给出流程），交付里只写「供采纳」= 未沉淀。
2. **三问必答**（零作答即 REJECT）：
   - ① 本次踩坑是否因未读 skill？（grep 会话存档佐证读过/没读过；若读过，如实说真实原因）
   - ② 是否遇到 skill/记忆外新东西？（逐条列出 skill 未覆盖的新形态；没有也要明说）
   - ③ 处理前是否先查 skill？（列会话时序证据）
3. **不沉淀要立据**：若结论是「不改任何 skill 文件」，必须给出「三问全否」的推理过程；有经验叙述而无
   「本次无沉淀且理由为……」的立据 = 违规。
4. **穷举或点名，择一声明**：集合类声称（「全部 N 条」「都真实发生」）不给枚举命令/计数 = 按未回答上界处理。
   要么给上界枚举命令+计数（如整改指令全集 = judge.jsonl 全部 exit=2 行逐条），要么写明「以下是点名非穷举」
   并回答「还有哪些同类未纳入、为何不必写」。
5. **「不碰功能代码」≠「不可写 `.claude/`」**：update worker 持有 write/edit 工具，skill/rule/CLAUDE.md 增补本身就是沉淀产物而非功能代码——任何「本执行授权面不含 skill/rule 写入」「供持写授权的角色采纳」的说法都是虚构授权限制（块 `1788357052593-3-e2e-live-test` 2026-09-02 REJECT 实证，判官原话「update 的职责就是写；只说建议 leader 沉淀而自己没写 = REJECT」）。真无写权限/环境不可写时按 BLOCKED 如实申报并附证据，不得以「建议采纳」替代落地。
6. **穷举计数必须连加闭合**：宣称「全集 N 个」并分类处置时，各类小计（含「已写」类）连加必须等于 N；分类内以省略号缩写（如「gsap-core…gsap-utils（7）」）的个数必须对枚举名单**逐名清点**后填写，不得凭印象估填——块 `1788357052593-3-e2e-live-test` update 第 2 次执行即因 gsap 域实为 8 个写成 7、类别合计 27≠宣称全集 28 被判 REJECT（judge.jsonl 2026-09-02T16:14:15，判官引 update 层规则 5/共同核心第 7 条「穷举声明计数不闭合」）。落笔前先把分类小计连加一遍，与全集枚举命令的输出总数双向核对一致，才可写「全部处置」。
7. **枚举命令必须真实可复跑、归属分区必须互斥**：①上界枚举的 CMD 必须是本会话真实执行且语法成立的命令（find 用 `-name`/`-path`，禁写 `find -pattern` 之类不存在的选项），OUT 必须是该命令逐行原样输出，判官照文粘贴必须复现同值——块 `1788357052593-3-e2e-live-test` update 第 3 次执行即因「`find -pattern` 命令虚构 + 输出逗号拼行非原样」被判「声称实测命令与实际输出不自洽，枚举命令不可复跑」（judge.jsonl 2026-09-02T16:26:39）；②全集分类必须分区互斥：每个文件在全部求和类别中恰归属一类，「域小计」（如 skills 域 21）与「处置类」（如已写 2）是两种口径，同一次连加只许采用一种口径，禁止把域小计与处置类混加——同块即因 skill-evolve 同计「skills 域 21」与「已写 2」两处被判「穷举计数仍不闭合」（同判决）。数字单源/先落清单再归类的同族既有教训见 card-rebuild §4 实例五/七与 CLAUDE.md「update 层交付四要点」必答 3/4。
8. **引用数值/哈希必须三声明（形态·验证命令·验证域），「已核验」必须嵌本会话工具原样输出**：update 交付引用的每个 sha256/行数/字节数逐个标注：①**形态**（文件对象 sha256≠git commit/object——裸列不标形态，判官三角③-a 按 commit 形态在 worksite 仓 `git merge-base/cat-file` 现查 exit=128，即判「声称存在与内容不符」并连带证伪全链；块 `1788633540977-V1R-e2e-ab-close-retry` update 第 1 次执行 8 个裸列数值被如此现查全不命中，其中 a0e1fe09 与 a0e1fe09f945 同值异长、273814948 实为 mtime 纳秒尾段——无标签数值会被判官一律当可现查对象，judge.jsonl 2026-09-05T19:49:14）；②**判官可复算的验证命令＋全路径**（文件 sha256=`sha256sum <全路径>`）；③**验证域**（哪个仓/目录）——pipeline 区非 git 仓且在判官取证通道触达范围外时，其数值只可转述并标注「引上游 §x 实测，本层未复算」。同时凡「已核验/已回读/在盘」类声称必须把本会话 read/grep/find/ls 的工具参数＋原样结果＋file:line 嵌交付正文，只给行号清单或结论短语=转述体 REJECT（同判决；无 bash 层锚点二分细节见 CLAUDE.md 备案区 b4-update-resume 条与 rate-limit-reclose「无 bash 层证据锚点二分」条）。
9. **查重命中≠免除写入（「已由前轮落典」抗辩无效）**：任务卡明文「实际写入 .claude」时，查重命中正典只免除**正典本体**的重复写入，不免除本步**增量**落地义务——增量=本块处置史备案行＋本轮判官 REJECT 中正典未覆盖的新教训，与「正典零重复」同时成立才算闭合；有新经验叙述而 .claude 零写入=漏答（判官原话「结论『本文件为唯一落点，不重复写 .claude 面』与任务卡『实际写入 .claude』不符，构成漏答/自造口径」，同判决）——「避免重复」偷换「免除写入」＝纪律 5「卡面指定交付路径」调和型的查重变体；零写入仅当纪律 3「三问全否」立据成立。
