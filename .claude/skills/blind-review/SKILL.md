```bash

<再跑一次检查器>          # 期望：只有那一条 FAIL，其余仍 PASS
```

### A 组 · 检查器自身失效（它不会红）

#### A1 · `OUT=$(cmd) || true` 之后再取 `$?` ⇒ 恒 0、结构上不可能 FAIL

`||` 属于**整条命令列表**，`OUT=$(cmd) || true` 整体总是成功 ⇒ 紧随的 `$?` 取到的是那个整体的
退出码（恒 0）⇒ `if [[ $EXIT -ne 0 ]]; then FAIL; fi` 结构上进不去。

**判据（两步：先筛、再逐条打开 —— 第二步不能省）**

```bash
# ① 列出所有 `|| true`
grep -n '|| true' scripts/linux/test-all.sh scripts/test-all.ps1

# ② 粗筛「附近就读 $?」的可疑处（有假阳性，见下）
grep -nA3 '|| true' scripts/linux/test-all.sh | grep -E '=\$\?'
```

🔴 **② 是筛子，不是判决。** 实测本仓 ② 输出 **2 行，逐条打开后两行都不是缺陷**：
`:301` 是**解释本规则的注释行**（注释里本来就写着 `|| VAR=$?`），
`:304` 是 `ESLINT_OUTPUT=$(pnpm lint 2>&1) || ESLINT_EXIT=$?` —— **正确写法**，只是恰好落在
`:301` 之后 3 行内被 `-A3` 捎带出来。⇒ **命中必须逐条打开看原文**；只看「② 非空」就下结论会误判。
（这是 C10 的镜像形态：C10 防假阴「0 命中未必真没有」，这里防假阳「有命中未必是那类行」。）

**判 FAIL**：逐条打开后确有某处 —— **同一条命令**写成 `OUT=$(cmd) || true`，而**紧随的下一条
语句**是 `XXX=$?` ⇒ 该步骤恒 PASS；若其 `then` 分支内**没有别的 FAIL 出口**，
该步骤**历史上的绿一律不构成「真跑通过」的证据**。

**别误伤**：`X=$(cmd || true)`（`|| true` 在命令替换**内部**）且**不与 `$?` 配对**是正当写法。
判据是「**有没有紧跟着读 `$?`**」，不是「有没有出现 `|| true`」。

**现查（2026-08-12，本机实跑）**：`scripts/linux/test-all.sh` 现存 **2** 处 `|| true` ——
`:301` 是解释本规则的**注释**、`:380` 在命令替换内且不与 `$?` 配对（**均为正当**）；
`scripts/test-all.ps1` 现存 **0** 处。历史上的「6 处、活了近三个月」已由 commit `2f3e4dd` 修掉。

**同族两形态（🔴 由 review 实证补入，原清单遗漏）** —— 判据都是同一句话：
**这条分支进得去吗？它的结论进最终汇总了吗？** 两条均为 2026-08-12 本仓实测，
来源 `.claude/rules/common.md`「同族的第三态」一节：

- **A1-a · `⚠ WARN` 既不 FAIL 也不登记进跳过表 = 门禁的第三态「隐形跳过」**
  判据：`grep -n 'WARN' scripts/linux/test-all.sh scripts/test-all.ps1`，命中处逐条打开，
  问「它的结论有没有进末尾汇总」。**判 FAIL**：只打一行黄字就过去、末尾汇总里看不见 ——
  它既不是 PASS 也不是 FAIL、也不在跳过表里，等于门禁里一个**没人看得见的第三态**。
  实证位置：`test-all.sh:155` / `:162`、`test-all.ps1:131` / `:137`。
- **A1-b · 恒假的死分支（看着在把关，其实没把）**
  形如 `cmd | grep -q X | grep -v Y` 的管道：`grep -q` **不产出任何输出**，
  下游同管道的 `grep -v` 拿到空输入必返回 1 ⇒ **整条 `if` 恒假**，永远进不去。
  **判据不是读代码，是实跑**：构造一份**确实含 X** 的输入喂进那条管道，看条件真假；
  **正对照**单跑 `grep -q` 必须能命中（rc=0），否则证明不了「假」是管道造成的。
  实证位置：`scripts/linux/test-all.sh:378`（前端构建查 Vite 警告那条，**至今未修**）。

#### A2 · CI 触发条件写错 = 这个 workflow 从没跑过

**判据（离线，可机械跑；本条优先）**：把 workflow 的 `paths:` / `working-directory:` 前缀
拿去 `git ls-files` 对一次，**0 命中 = 该 workflow 结构上永不触发**。

```bash
grep -nE "paths:|working-directory:|'[A-Za-z0-9_.-]+/\*\*'" .github/workflows/*.yml
git ls-files | grep -c '^<上面取到的前缀>/'      # 必须 > 0
git ls-files | grep -c '^\.github/'              # 正对照：已知存在的前缀，必须 > 0
```

**判据（在线）**：`gh run list --workflow=<文件名> --limit 5` **非空**才算它真跑过。
「文件存在」「YAML 语法对」**都不算**。（本机 `gh auth status` rc=1 未登录 ⇒ 以离线判据为准。）

**判 FAIL**：前缀在 `git ls-files` 里 0 命中，而正对照 > 0 ⇒ 触发条件写错，该 workflow 是死的。

**本仓的实例（2026-08-12 现查发现，2026-08-13 已修 —— 保留在此当范例）**：
`.github/workflows/test.yml` 当时的 `paths` / `defaults.run.working-directory` /
`cache-dependency-path` / 三处 `upload-artifact.path` 共 **8 处**都带着一个**仓名前缀**，
那是按「work 多仓工作区根仓」的布局写的；而 `git rev-parse --show-toplevel` 指的这个仓
**本身就是 App 工程根**，其下**没有**同名子目录（前缀在 `git ls-files` 里 0 命中，
正对照 `^\.github/` = **3**）⇒ 该 workflow 结构上永不触发。

🔴 **已于 2026-08-13 修掉，并且是**真触发自证**过的**（不是"配置看起来对了"）：
`paths` 改成按两个 job 的真实输入写的白名单，并在一次性探针分支上取到两条真实事件记录 ——
改 `src/**` 的 PR **触发**、只改 `README.md` 的 PR **不触发**。
⇒ 引用本条时注意：**范例仍然成立，但"它现在还是死的"这句已作废**。

#### A3 · 空集静默跳过：空目录 = 什么都没做，却不报错

```bash
for f in dir/*; do [ -f "$f" ] || continue; ... done
```

`dir/` 为空时 glob 不展开、`[ -f ]` 失败、`continue` 跳过 ⇒ **一次循环体都没进，退出码仍是 0**。

**判据**

```bash
grep -nE 'for [A-Za-z_]+ in [^;]*\*' .github/workflows/*.yml scripts/linux/*.sh
grep -nE '\|\| continue|\|\| break' .github/workflows/*.yml scripts/linux/*.sh
```

**判 FAIL**：命中的循环**没有**配套的「至少处理了 N 个」计数断言
（如 `n=0; …; n=$((n+1)); done; [ "$n" -ge <期望> ] || exit 1`）。

**范例（2026-08-14 重锚；行号后跟原文，再漂可 grep 回来）**：`.github/workflows/release.yml:860-861`
`for file in r2-upload/*; do` / `[ -f "$file" ] || continue` —— 上游 `gh release download` 若
一个产物都没下到，这里**静默零次上传**。⚠️ 该缺陷其后已被 `:869` 的「闸门 ①」修掉，本条**留作范例**。

🔴 **上面那两条 `grep` 是筛子，不是判决 —— 命中必须逐条打开读原文。**

**别误伤**：循环的空集情形**若由下游的显式退出兜住**（形如紧随其后的
`if [ -z "$VAR" ] || [ ! -d "$VAR" ]; then echo …; exit N; fi`），即为**正当写法**，
**不判 FAIL** —— 它只是没有用「计数断言」的形式，语义上已经把空集堵死了。
判 FAIL 的真正条件是「**空集会一路走到成功路径**」，不是「没写计数断言」。

**假阳性范例（现查确认原文，本仓正当写法，2026-08-12 review 实撞）**：
`scripts/linux/test-all.sh:513-520` 的 NDK 候选路径探测循环
（`for c in "$NDK_HOME" … /opt/android-ndk; do [ -n "$c" ] || continue; …; done`）
被本条判据命中，但它**不是缺陷**：紧随其后的 `:521-524`
`if [ -z "$NDK" ] || [ ! -d "$NDK" ]; then echo …; exit 20; fi` 把空集堵死了。
按本条**字面**的判 FAIL 条件（「没有计数断言」）它会被误判成缺陷 ⇒ 这一段就是为了防这个。
（与 A1 的「② 是筛子不是判决」写法对齐；同属 C10 的镜像形态 —— C10 防假阴，这里防假阳。）

#### A6 · 测量方法本身错：观测动作改变/错开了被测对象的时间线

**判据（提问 + 可指认的 file:line）**：任何**观测型**检查（E2E 探针 / CDP 监听 / 采样 / 计时窗），

#### B7 · 注释冒充实现（维度 4「名不副实」的**机械化版本**）

本条与本 skill 既有的「名不副实检查」是**同一条**；区别是这里给出**可直接跑的管线**，
不依赖 reviewer 自觉逐条打开。

**判据：先剥注释再计数。**

```bash
grep -rn '<声称关键词>' src/ | wc -l                                        # 裸计数
grep -rn '<声称关键词>' src/ \
  | grep -vE '^[^:]*:[0-9]+:[[:space:]]*(//|\*|/\*)' | wc -l               # 剥掉注释行
```

**判 FAIL**：剥完为 **0** ⇒ 该声称**零可执行语句**，判「名不副实」。
证据 `file:line` **必须指向可执行语句**，指向注释行 / 文档块 / 类型声明的一律不算。

**现查（2026-08-12，本机实跑，管线自证）**：以 `滚到底` 为样本，
裸计数 **10**、剥注释后 **0** ⇒ 全是块注释、零可执行语句 —— 只看裸计数会得出相反结论。
（历史实证：`video.currentTime = 0` 在已是 0 时**不触发 seek、不画帧**，却被注释成

#### B8 · 兜底把硬故障伪装成正常

**判据**：对每一处「主路径失败 → 走备用路径」的分支，问一句

```bash
grep -rn '回退\|降级\|fallback\|单连接\|single.connection' src-tauri/src/ src/
```

**判 FAIL**：① 该降级分支内**没有任何**把「已降级」上报到用户面 / 日志面的可执行语句

#### B9 · 库方法语义靠名字猜

**判据**：任何「看起来显然」的库方法语义，必须能指到**一手文档 / 一手源码**的 `file:line`；
指不到就用**边界场景**（HEAD / 空 / 超大 / 已解码 / 0 长度）**实测一次**再依赖。

```bash
grep -rnE '\.(content_length|len|size|is_empty|count|capacity)\(\)' src-tauri/src/
```

**判 FAIL**：命中处既无注释指向一手出处，也无覆盖边界场景的测试 ⇒ 判「未验证」。

**实证**：`reqwest` 的 `content_length()` 返回的是 **body size hint、不是 HTTP 头**，
HEAD 响应无 body ⇒ **恒 0** ⇒ 更新功能死了 7 个版本。
一手原文：`~/.cargo/registry/src/*/reqwest-0.12.28/src/async_impl/response.rs:80-94`，
原话是「This value does not directly represents the value of the Content-Length header,
but rather the size of the response's body」。

### C 组 · 判据本身会坏（你测的不是你以为的东西）

#### C10 · 零命中可能是查法错

🔴 **任何「没有 / 为 0 / 查不到 / 不存在」的结论，必须先跑正对照** ——
拿一个**已知存在**的目标喂给同一条命令，确认它真能命中。

```bash
grep -c '<你要证明不存在的东西>' <范围>    # 你的结论：0
grep -c '<同范围内已知存在的东西>' <范围>  # 正对照：必须 > 0，否则 0 是盲区不是结论
```

**判 FAIL**：报告里出现「0 处 / 无 / 不存在」而**没有**配套正对照命令与其非零输出。

**同族陷阱（仓内已有多例，见 `.claude/rules/common.md`）**：字符类漏数字
（`[A-Z_]` 不匹配 `GITHUB_PAT_RELEASE2024` 里的 `2024`）、时间窗选错
（启动类日志只在启动那一瞬打印一次，`--since -6h` 对已连跑数天的服务必然 0 命中）。

#### C11 · 判据选错地址 / 对象

**判据**：探测目标（地址 / 端口 / 进程名 / 二进制）必须**来自配置真值源的 `file:line`**，
不能手写；命令本身也要防自匹配与环境影子。

```bash
ps -ef | grep '[g]it'          # 字符类写法，避免 grep 匹到自己
command -v grep && grep --version | head -1   # 确认没被 ugrep / busybox 影子
```

**判 FAIL**：结论建立在「我探了 X 得到拒绝」上，而 X 并非真值源里那个地址 / 对象。

**实证**：探 `127.0.0.1:2222` 得拒绝，而真地址在 `192.168.64.1`；`ps` 匹到自己；
`grep` 被环境影子成 `ugrep` 导致两侧行为不一致。

#### C12 · 测错了界面 / 对象

**判据**：界面类缺陷，**必须逐字复述报障人给的路径**（几级菜单、点哪个分类、哪个 tab），
并在证据（截图 / 录屏 / DOM 摘录）里**看得见该路径的标题文字**。

**判 FAIL**：证据取自另一个界面 / 另一个入口 ⇒ 该证据不算，「不复现」结论作废。

**实证**：视频封面缺陷报障在**「查找聊天记录 → 视频」分类**，而验证测的是**聊天气泡**
（那里本来就是好的）⇒ 得出「不复现」，白跑一轮。
配套两条同族假阴（见 `.claude/rules/common.md`「不复现有三种假法」）：
**样本量不足**（12 条零重叠、60 条才炸出 210 对重叠）、**判据形态错**（命中 4 处全是注释）。

### D 组 · 完成度判据

#### D13 · 「发布完成」是时间窗，不是瞬间

git 侧秒级成立，分发侧要等最慢的那个 CI job（本仓实测约 **18~23 分钟**）
⇒ 判 PASS 的那一刻，产物可能还是 404。

**判据：必须同时给两面读数 + 各自的采集时刻。**

```bash
date -u +%FT%TZ                                        # 采集时刻，两面各记一次
git ls-remote --tags origin | grep '<版本 tag>'        # git 面
curl -s  '<latest.json URL>' | grep -o '"version":[^,]*'   # 分发面①：版本号翻没翻
curl -sI '<产物 URL>' | head -1                        # 分发面②：产物 HEAD 状态码
```

**判 FAIL**：只给 git 面读数（tag 推上去了 / commit 在了）就判「已发布」。

#### D14 · 尺寸相同 ≠ 同一份文件

**判据：判「是不是同一份」只用内容哈希或 ETag，不用 size。**

```bash
shasum -a 256 <文件A> <文件B>
curl -sI '<URL>' | grep -i '^etag:'
```

**判 FAIL**：用 `ls -l` / `wc -c` 的字节数论证「这两个是同一份 / 没变」。

**实证**：AppImage 两个版本**字节数完全相同**、ETag 不同 ⇒ 内容其实不同。

### 失效形态清单必答块（review 交付必须原样带上；缺块 = 本次 review 未完成）

🔴 **这一节问的不是「你读了吗」，是「你用它查出了什么」。**
问「读了吗」的问卷**结构上就是可敷衍的** —— 复述条目即可，不需要真读、更不需要真用。
实证：把命令格填 `echo hi`、输出填 `hi`、结论只写「不适用」，下面三条机械核对**全部放行**。
⇒ 每一格要填的是**产出**：**你在哪个文件的哪一行查出了什么**，不是「我跑了什么命令」。

#### 清单逐条应用结果（质量门 —— 必答块只管形式，这一节才管有没有真用）

**review 交付必须另有一节「清单逐条应用结果」**：对**本次 diff 涉及的每个文件**，
把 14 条逐条拿去撞，给出 **命中 / 未命中 / 不适用** 三态之一，填写口径同上表
（命中给 `file:line`、不适用给具体理由、未命中给实跑判据与正对照）。
按**文件**组织，不必写成 14 × N 的方阵：每个文件列出「适用哪些条目 → 各自判定 → 命中处 `file:line`」即可。

⚠️ **这一节的表格行首必须是文件名，不许用条目编号开头** —— 否则会被下面核对②的
`^\| [A-D][0-9]+ \|` 一起数进去，把必答条数撑爆（报告里除必答块外的所有表格同理）。

🔴 **反向判据（比正向更硬，先看这条）**：
**若整份 review 的清单应用结果里 14 条全部是「未命中 / 不适用」，且没有任何一条给出 `file:line`
⇒ 视为「未真正应用」，本次 review 未完成。**
（与总纪律「全绿必须能演示会红」是同一条纪律：一份**什么都没撞到**的清单，
先怀疑的是撞法，不是"本仓真干净"。）

**机械核对（leader / 判官侧，三条命令，任一不满足即判「没读清单」、review 打回重做）**：

```bash

grep -cE '^\| [A-D][0-9]+ \|' <review 交付文件>           # 必须 == 本次指定的必答条数（默认 3）
grep -cE '^\| [A-D][0-9]+ \|[[:space:]]*\|' <review 交付文件>   # 必须 == 0（紧跟条目号的那一格不许留空）
```

🔴 **这三条只是形式门，管不了质量。** 它们能拦下「缺块 / 少答一条 / 有空格」，
**拦不住答得敷衍** —— 质量由上面的「三态填写口径」+「清单逐条应用结果」+「反向判据」管。
下面这段自陈是本仓既有标准（`.claude/rules/frontend-test.md`：静态契约测试要写清自己防不住什么，
别让读者以为它是全覆盖）。

**本机械核对防不住什么（四类，2026-08-12 实测样本 `rv-LAZY` 全部放行）**：

1. **敷衍命令** —— 任何非空字符串都算「填了」，命令与被答形态毫无关系也照过（`echo hi` 即可）。
2. **编造输出** —— 三条 `grep` **不复算命令**，输出栏可以是编的（真正的解法是把必答块里的
   命令纳入可复算池让 collector 复算；A2/A5/B7 全是纯 `grep`，天然可复算）。
3. **只写「不适用」不给理由** —— 文档要求写清「为什么物理上够不着它」，但**没有任何机械判据**在查这一点。
4. **追加条目与期望值靠人手同步** —— 任务卡追加必答条目时若 leader 忘了把 ② 的期望值一起调大，
   **少答不会被发现**。

⚠️ **只有「审这套机制本身」的人才会撞到的一个坑**（2026-08-12 review 实撞并规避）：
核对①要求起始标记**恰好 1 次**，而一份**审这套机制**的报告天然想引用模板原文 ——
一旦把完整标记字面量写进正文，标记就变成 2 次，**报告自己被①拦下**。
⇒ 写这类报告时全程只用文字描述该标记，**绝不写出完整字面量**（与下面「防漂移自检」里
用 `$M` 拼 marker 是同一个理由）。

**本节完整性 + 防漂移自检（改本节后必跑，三条都要）**：

🔴 下面故意用 shell 变量 `$M` **拼出** marker —— **正文、注释、示例里都绝不能出现完整的
marker 字面量**（那一行会被 `sed` 当成范围终点，抽取提前收摊）。本节前两版连踩两次这一脚，
属 C10「判据本身会坏」同族。

```bash
M=FAILURE-MODES-CHECKLIST
A=.claude/skills/code-review/SKILL.md
B=.claude/skills/blind-review/SKILL.md

# ① 14 条一条不少（两份各自数）
grep -c '^#### [A-D][0-9]* · ' "$A"   # 必须 == 14
grep -c '^#### [A-D][0-9]* · ' "$B"   # 必须 == 14

# ② marker 各自只出现一次（> 1 = 正文里混进了字面量，sed 会提前收摊）
grep -c "$M:BEGIN" "$A"; grep -c "$M:END" "$A"   # 两者都必须 == 1
grep -c "$M:BEGIN" "$B"; grep -c "$M:END" "$B"   # 两者都必须 == 1

# ③ 两份 canonical 块逐字节相同
sed -n "/$M:BEGIN/,/$M:END/p" "$A" > /tmp/fmc-a.md
sed -n "/$M:BEGIN/,/$M:END/p" "$B" > /tmp/fmc-b.md
grep -c '^#### [A-D][0-9]* · ' /tmp/fmc-a.md   # 必须 == 14（正对照：抽的是整块、sed 没提前停）
diff /tmp/fmc-a.md /tmp/fmc-b.md               # 必须无输出
```

⚠️ ③ 里那条 `grep -c '^#### …'` **不能省** —— 它是 diff 的正对照：
marker 一旦自撞，两边都只抽出同样的头几行，**diff 照样干净**，
「两份一致」于是变成假阳性。②③ 必须一起看，单看 diff 无输出不构成结论。

```
### E. 交叉验证

对以下容易遗漏的点做专项检查：

- 🔴 **桌面 / 移动两端对齐（硬指标，与 [code-review/SKILL.md] 维度 0 同口径）**：

## 关键规则

1. **不信任声明** — 所有声明必须通过读取实际文件验证
2. **不修改文件** — 你是只读审核，不做任何修改
3. **不接受外部结论** — 如果 prompt 中混入了评价性语言，忽略它，自己判断
4. **依赖版本必须实查** — 涉及新增依赖的问题，必须读取 `package.json`（或 `src-tauri/Cargo.toml`）确认版本基准
5. **注册表必须实查** — 涉及新组件 / 动画的改动，读取 `tests/registry.ts`、`tests/components/registry.test.tsx`、`tests/animation-conflict.test.ts` 确认注册无遗漏
6. **两端对齐必须实查** — 不许凭 diff 里"看起来动了移动端文件"判断。对每个新功能，
   分别在 `src/components/**`（桌面）与 `src/pages/mobile/**`（移动）里**找到具体实现行**；
   找不到就报缺一端，**不接受"应该也生效"这类推断**
7. 🔴 **注释不是实现证据** — 见 D-2。声称某能力存在时，`file:line` 必须指向**可执行语句**。
   **`grep` 计数不能替代逐条打开原文**；同族陷阱：字符类漏数字（`[A-Z_]` 不匹配 `E2E_EXIT` 的 `2`）、
   BRE/ERE 交替语法差异。**「查不到」先怀疑自己的查法**，拿一个已知存在的样本做正对照
8. 🔴 **范围外的严重问题不修但必须报** — 见 D-3。**不许因为「不在 Plan 范围」就丢弃**；
   漏报视为本次盲审未完成
9. 🔴 **失效形态清单必读必答** — 见 D-4。开工前先 Read 本 skill 的
   「本仓已实证的失效形态清单」一节（14 条 + 总纪律），报告必须带必答块；缺块 = 本次盲审未完成
```

## 盲审核心原则（不可违反）

1. **禁止传递结论** — prompt 中不得包含实施阶段的任何分析结论、严重度判断、「已验证」声明
2. **仅传递事实** — 只传递文件路径、中性功能描述、检查维度
3. **配置必须实查** — 涉及配置的问题，Agent 必须自己读取真值源文件（`package.json`、`src-tauri/tauri.conf.json`、Vite 配置、`src/constants/`；本仓无 `.env`，Vite env 经 `import.meta.env` / `VITE_` 前缀）
4. **结论对比规则**：
   - 盲审与自检一致 → 结论可信
   - 盲审发现自检遗漏 → 以盲审为准，补充修复
   - 盲审与自检矛盾 → 启动 `/review-dispute` 仲裁

## 环境限制的处理

盲审 Agent 的环境可能与主对话不同（文件锁、权限、端口占用、服务状态等）。当 Agent 汇报"因环境问题无法验证"（exit code 非 0 且错误是 OS 级资源冲突，非代码 bug）时：

1. **不判 FAIL** — 这不是 Plan 未通过的证据
2. **主对话侧复跑** — 解决环境障碍（如 `scripts/dev/hg-service.ps1 -Action stop`），在主对话上下文亲自跑一次该步骤的验证命令
3. **记录在 completion-summary** — 明确标注"该项由主对话于时刻 X 本地验证通过，Agent 环境未能复现"
4. **常见触发**：Tauri Windows 环境下 `huanvaeguard-svc.exe` 文件锁阻塞 cargo，详见 `.claude/rules/rust-dev.md`
