对以下模块执行全面健康检查：

**目标模块**: $ARGUMENTS

---

## 第一轮：并行排查

按以下维度启动多个并行 Agent 进行排查。每个 Agent 必须先阅读目标模块的完整代码（handler → service → model），再做评估。

### Agent 1 — 安全审查
- 认证/授权逻辑是否完整（是否所有路由都有正确的 guard）
- 输入验证是否充分（请求结构体是否使用 `validator`）
- 密钥/Token 管理是否安全（是否有硬编码、是否有回退默认值）
- SQL 注入/越权风险（是否有动态拼接 SQL、是否校验资源归属）

### Agent 2 — 性能审查
- 数据库查询效率（N+1 查询、缺少索引、事务粒度过大）
- 并发安全（锁粒度、竞态条件、advisory lock 使用）
- 内存/连接泄漏（未释放的资源、无界缓冲区）

### Agent 3 — 代码质量审查
- 错误处理完整性（`unwrap()` 使用是否合理、错误是否正确传播）
- 死代码/未使用的字段/重复逻辑
- 文档与代码一致性（README、注释、数据结构说明）

### Agent 4 — 测试覆盖审查
- 关键路径是否有测试覆盖
- 边界条件和错误路径是否测试
- 是否有 pre-existing 测试失败（检查对应模块 rule 文件的「已知测试失败」表）
- 测试资源是否正确清理

每个 Agent 输出格式：
```
| 编号 | 问题 | 严重度 | 文件:行号 | 简述 |
|------|------|--------|-----------|------|
```

---

## 第二轮：盲审确认

对第一轮发现的每个问题，启动**零上下文独立 Agent** 进行盲审。

**必须严格遵循 CLAUDE.md 中的盲审规则（防止确认偏差）：**

1. **禁止传递第一轮的结论和分析** — 二轮 Agent 的 prompt 中只包含：
   - 代码文件路径和行号范围
   - 功能的中性描述（如"评估此函数的事务边界"），不带有"竞态条件"、"漏洞"等预设词
   - 需要检查的维度（如"事务边界"、"锁范围"、"错误处理"）
2. **禁止传递严重度标签** — 不告诉 Agent 第一轮认为是 CRITICAL/HIGH/LOW
3. **任务定义为独立评估** — prompt 措辞必须是"独立评估这段代码是否存在问题"，而非"验证是否存在 XXX 问题"
4. **必须检查实际运行环境** — 涉及配置/环境变量的问题，Agent 必须读取 `.env`、部署配置等实际文件

**盲审 Agent 的 prompt 模板：**
```
独立评估以下代码：
- 文件：{文件路径}
- 行范围：{起始行}-{结束行}
- 功能描述：{中性功能描述}

请从零开始阅读代码，评估以下维度：{检查维度列表}
如涉及环境变量或配置，请同时读取相关配置文件确认实际运行时状态。
输出你的独立判断：是否存在问题？如有，具体是什么？如无，说明为什么是安全的。
```

盲审后对比两轮结论：
- **两轮一致认为有问题** → 标记为真实问题
- **二轮认为无问题** → 标记为误判，附二轮 Agent 的反驳理由
- **两轮结论矛盾** → 启动第三个 Agent 仲裁，或直接标记待用户裁定

---

## 输出

汇总真实问题清单，按严重度排序：

| 编号 | 问题 | 严重度 | 文件 | 修复方案 | 修复风险 | 收益评估 | 结论 |
|------|------|--------|------|----------|----------|----------|------|

**结论**列说明：
- **建议修复** — 修复收益大于风险
- **暂不修复** — 修复风险大于收益，附理由
- **待用户裁定** — 两轮结论矛盾或需要业务判断

---

**输出完毕后，明确询问用户：**

> 以上是「{模块名}」的健康检查报告。请确认哪些问题需要修复？确认后我将对每个需修复的问题走 `/audit` 审计流程。

**在用户确认前，不进行任何代码修改。**
