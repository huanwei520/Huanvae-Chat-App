# 聚合块（汇总兄弟块产出）：竞态应对与取证口径

来源：块 `1790367135173-2mnf7rct-4-汇总四份查验成总报告`（2026-09-25 实战：兄弟块三件与本块同批并行派发，本块两次起跑 cross-evidence 均空，code 层转一手查验四轮整改过审；update 层首版三违 REJECT 后本 skill 落地）。近亲正典（先读再引用，勿重复）：`readonly-audit-evidence`（报告体查验取证形态）、`skill-evolve`「沉淀层交付纪律」、CLAUDE.md update 层交付四要点（:571 起）。本 skill 收聚合块特有形态。

## §1 cross-evidence 注入三时态与判别

| 时态 | 现场特征 | 判别与去向 |
|---|---|---|
| 空 | README「当前收录: (尚无兄弟块终态)」 | 兄弟块未终态 → §2 分支 A |
| 状态摘编 | 仅 `*.json`（约 200B：blockId/status/note/finishedAt）＋ README | 有状态无正文 → §3 分支 B；`wc -c` 即辨（正文级分章通常 ≥10KB） |
| 正文 | 分章报告文件体积异常 | 才可常规逐节对照汇总 |

注入时刻可能晚于本块交付完稿（本块实案：注入 21:19:32Z 晚于完稿 21:17:28Z）。**以 cat/ls 实测时点为准，不以任务卡「引擎会注入兄弟块终态件」的假设为准**；聚合块与兄弟块同批并行派发时，起跑早于兄弟终态是常态而非异常。

## §2 分支 A：如实 BLOCKED，不虚构「已汇总」

兄弟块未终态时禁止凭空代写兄弟块内容冒充汇总；首轮起跑如实 BLOCKED 是合法申报，不是失败。需继续产出时转 §3。

## §3 分支 B：状态-only 注入时转「一手查验＋零取材声明」

三要件，缺一即失保真：
1. **头部溯源声明**：明写「对 cross-evidence 取材量为零，全部结论系本块对仓库一手只读查验」；附注入件清单（ls 回显）与关键时序（兄弟块终态时刻 vs 本报告完稿时刻，含中间多次注入的再现察记录）。
2. **验收口径显式降级**：任务卡「与三份分章一致无篡改」在无正文对象时字面不可执行；以「总报告与仓库现状一致」的一手复核替代（锚点抽核＋负面结论复跑＋计数口径复跑），在交付中写明替代及理由。声明在前、复核在后，判官才可核。
3. **措辞留互证口**：对兄弟块后续终态写「可互相印证而非冲突」，不写死排他结论。

## §4 汇总报告交付形态

- **可加和复核表**：工作量估算每个小计旁标等式（如 `17~27 = 3~5 + 6~10 + 8~12`）；归并区间禁止凭印象压缩（2~3＋3~5 归并写 3~5 不写 2~3；上限进位 57~89 应为 58~101 类错误 review 层会逐项加和抓出）。
- **owner 摘要字数双口径**：「N 字内」类约束同时报汉字数与非空白字符数（python re 双计数实测），并注明元信息注记（测量方法说明）不计入摘要正文口径。
- **转写数字标来源**：引自上游交付的计数/结论一律「转述＋来源 §x」；本层复算过的才署「本层实测」并附 CMD+OUT。同一数字连口径一起转写（如 transition 412 = 带冒号模式、src 递归 css+tsx）。
- **兄弟块缺要素标「待补」**：卡片明文要求；不编造补齐。

## §5 read 工具显示伪影：报告编码缺陷前先字节核验

read 输出中正文汉字显示为 U+FFFD 替换符（实案：「华为」显示作「华��」）可能是**显示层截断伪影而非文件缺陷**；下编码结论前必须 `cat -v` 或 python `open(..., encoding='utf-8')` 取行 repr 逐字节复验（本块实案：字节完好，纯伪影）。同族纪律：判据以字节为准，不以显示回显为准。

## §6 聚合块开工清单（按序）

1. `ls cross-evidence/` ＋ `wc -c` 判时态（§1）；
2. 空 → §2 BLOCKED；状态-only → §3；正文齐 → 常规逐节对照；
3. 本块含 update 层时，动笔前实读 CLAUDE.md update 四要点节＋`skill-evolve`「沉淀层交付纪律」；
4. 汇总数字一律双轨：转述标源、复算附 CMD+OUT；
5. 收尾自查三问（①是否因没读 skill、②是否正典外新知、③处理前是否查过 skill）与落点 file:line。
