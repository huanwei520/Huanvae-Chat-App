VERSION=1.1.39
MESSAGE=v1.1.39: 修 Windows 应用内更新会删掉桌面图标与开始菜单项。根因是本仓 hooks.nsi 的 PREINSTALL 跑旧卸载器时命令行漏传 /UPDATE：新安装器拿到 /UPDATE 后 $UpdateMode=1，而旧卸载器没拿到、$UpdateMode=0，于是按「用户在主动卸载」把桌面/开始菜单快捷方式、任务栏固定项、HKCU Run 自启项整块删掉；回到新安装器，模板里两处建快捷方式的调用在 $UpdateMode=1 下直接 Return 不重建，于是删了不建，且安装日志一个字都不会说。上游模板自己跑旧卸载器时是补 /UPDATE 的，本仓钩子漏了这一步。改法：按 $UpdateMode 组装命令行，=1 时带 /UPDATE 且必须排在 _?= 之前（NSIS 手册 3.2.2：_?= 必须是命令行最后一个参数）；其余判定逻辑一字未动，tauri.conf.json 零改动，不改变安装器身份与安装范围。真机单变量复现（Windows Server 2025，同一台机同一份字节，除命令行一个 token 外零变量，每臂两遍）：不带 /UPDATE 四个 lnk 位置 1/1 归零；带 /UPDATE 保持 1/1 且旧版照样卸干净；错序（_?= 在前）落在第三态——lnk 保住但旧程序文件一个没删，而 rc=0、注册表卸载记录已删、钩子四段判定全部放行还打印「已卸载」，是一条会自己伪装成成功的失败。守卫：winService.nsisContract.test.ts 新增 8 条断言与一个渲染器，不做文本 grep 而是把命令行组装逻辑按 $UpdateMode=0/1 各解释一遍产出真实命令行再断言，遇到不认识的语句直接抛错；变异自证整段退回 29/5、只换顺序 32/2、还原 34/0，既有 21 条一条未被带红。另把机制、真机读数、载体事实与未闭合项 EOF 追加进 .claude/rules/rust-dev.md。🔴 未验证项，不写成已验收：第 13 项 VPN 连通性本次未执行（HG_PEER_VIP 无默认值且本机 App 守护进程 active:false，退出码 3=未执行，经授权按 skip 放行），真跑 12/13，不是 13/13；「开始菜单搜索框搜不到」那一层零覆盖（真机载体是 Server Core，无 explorer 外壳、无该 UI，未用 lnk 存在性顶替）；用 Tauri 真产的打了补丁的安装包走一遍完整更新这一格在本次发布前仍未闭合，留待本 tag 的 CI 产物出来后补验；Windows 之外平台不受本改动影响。
