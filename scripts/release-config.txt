MESSAGE=别人回复你的历史消息，引用块终于显示出来了 —— 真因不是渲染层，是存量脏数据：v1.1.25~28 期间几条写入路径把 reply_to 与相册三件套写死成 NULL，2026-08-10 只修好了「以后写进来的」，已经躺在库里的那些行永远是 NULL（sync 只拉 seq > last_seq 不回头，历史加载又 INSERT OR IGNORE 跳过已存在行），于是「自己发的看得见、别人回复的看不见」。修法：save_messages_skip_existing 由 INSERT OR IGNORE 改成 ON CONFLICT DO UPDATE，只对 reply_to / media_group_id / media_group_index / media_group_count 四列做 COALESCE(本地,服务端) 补空，content / seq / is_recalled / is_deleted 一律不动（本地撤回状态绝不被服务端响应覆盖）；配 sync 侧 100 条回溯窗口每会话回填一次，并把原先在增量同步与分页续拉两处各抄一遍的字段映射收成单一 toLocalMessage —— 那两份抄写正是历史上反复丢字段的成因。+ 已读标记改口径：只挂「我发出的最新一条」（更早的自己消息不再逐条堆绿勾，锚点在列表 map 之外算一次 O(n) 而非每条各扫一遍），且无人已读时整个隐藏，不再显示零信息量的「0 人已读」与灰色双勾。+ 更新下载器删掉单连接回退：Range 分片成为唯一路径，探测不到 accept-ranges 或长度未知/为 0 一律报错中止并给「已中止更新 + 手动下载」文案，绝不静默降级；桌面与安卓各配一条「改回降级即翻红」的守卫测试。+ 清掉「消息定位」4 处过期注释（仍在描述已删除的 loadUntilMessage 循环翻页语义，其中一处直接点名了这个不存在的函数）。已知未做：桌面端整批截图（总管调度中）、iOS、相册发送侧入口；门禁 clippy-android 与 vpn-connectivity 两项本机物理跑不了，已显式 ALLOW_SKIP 放行并如实记账，真跑 11/13。
