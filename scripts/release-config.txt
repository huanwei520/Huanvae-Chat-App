MESSAGE=群聊消息的发送者昵称移进气泡内部（参考 Telegram 的形态），相连气泡之间的间隙同时收窄。① 昵称落点与时间戳走同一条既有规则：文本气泡落气泡内顶部；有配文的媒体落大气泡内顶部；无配文媒体落媒体左上角的半透明药丸（时间戳药丸在右下角）；文档/会议邀请/卡片这三类是独立白底卡片、没有气泡可进，昵称仍留在卡片上方一行——与时间戳留在卡片下方是对称的，不是这里单开的例外。② 连发组内相邻两条的下边距 16px → 4px，组间维持 16px；收窄的那一行由 senderRunGate.runTightKeys 一次算出，与头像锚点同源同序（撤回行两侧都不贴紧）。该规则同时应用到 1:1 私聊——他原话的上下文是群聊，此处如实披露。③ 修掉一处本功能自己引入的缺陷：无配文媒体上，昵称药丸的宽度上限只镜像了自己的两个 6px 内缩，没有把右上角那个本地缓存角标占的位置算进去，长昵称的尾巴会被角标压住。用 getBoundingClientRect 实采坐标做矩形算术坐实：修复前药丸 right=670 而角标 left=652，重叠 18×18px；修复后 right=648，余量 4px。预留量不再重打一个数字，而是由角标自己那条规则导出的 --file-local-badge-reserve 推导，角标改大药丸自动让位；配套回归做了变异自证（还原修复 ⇒ 两条断言分别从 token 引用与算术两个角度翻红，还原后 sha256 逐字节回位）。④ 同批补完：药丸配色从写死的七个 hex 收敛到单一 token 真值源（此前浅色主题会错拿深底色）；长昵称截断契约覆盖三个落点而不只是原来那一处；animation-conflict 注册表把「登记项抓不到规则块仍恒 PASS」这类空转整类堵死；并补回两条此前被删却无人接管的断言。验证与如实披露：typecheck 0、eslint --max-warnings 0、vitest 325 个文件 3575 条全过、前端构建通过；桌面端真机做了改前/改后同场景对照（一人连发三条、A2→C1→A2 断组、极短消息「好」、超长昵称截断、无配文媒体药丸），Web Inspector 控制台在场景重现时间窗内 ERROR=0 / WARN=12，12 条全部是页面重载时 Tauri 回调桥的告警、与本次改动的文件无关（做 A/B 对照要反复热重载才产生）。🔴 未验证项，不写成已验收：手机端真机零证据（模拟器批次未执行）；「无配文媒体药丸」这一路只在桌面 dev 载体上核过像素，未在 release 包上复核；药丸那套深底配色未做任何对比度量化。另：.github/workflows/test.yml 的 paths 前缀在仓内零命中（event=push 的 run 数为 0，正对照 release.yml 为 80），该 workflow 对 push 从未触发过，本次真正的把关面是 release.sh 本地跑的全量门禁，不能说成「CI 会拦」。
