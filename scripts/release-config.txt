VERSION=1.1.33
MESSAGE=这一版把上一版中断在半路的五条线补完，并接上后端一条不做兼容的契约变更。① 更新下发地址不再指向任何镜像：此前 latest.json / android-latest.json 里给客户端的 url 前面挂着 cdn.gh-proxy.org，也就是用户真正去下载更新的那个地址是代理；现在六条下发 url 全部直连原始仓库，死配置 PROXY_URLS（定义了全文件无读取点）与那份公开的「镜像菜单」latest-all-proxies.json 一并删除，不留任何可切回镜像的开关。补了机器守卫并做变异自证：把 ${PROXY} 加回一条 url，全量 312 个测试文件只红 1 个、该文件 4 条只红 1 条。顺带删掉 Release 正文那句「可使用代理链接」——去代理后它已经变成假话。② 上传中的占位与上传完成的气泡不再跳版、也不再破图。两个根因都是拿改动前的原文对出来的：待发区那把 object URL 在发送收尾被 clear 吊销，却被递给了发送态，于是在途 <img> 指向一个已吊销的 blob；容器尺寸则是在途走固定默认值、完成态走 calculateDisplaySize，两套算法。改法是换所有权（发送态自己从 File 造 URL、自己释放）+ 两态走同一个函数、尺寸同源。review 另挖出一条现有 69 条测试结构上看不见的缺口：待发区尺寸探测是 fire-and-forget，用户粘贴后立刻回车时 seed 里宽高仍是 null ⇒ 跳变原样复发，已在 enqueue 侧补一次探测并补了第一条能走到 null 路径的测试。③ 视频封面持久化「只有 Windows 生效」这条报障，经三步取证证伪：查盘查库（6 个封面文件、video_posters 6 行、created_at 分散而非被反复刷新）、杀掉 App 重开后逐字节不变、以及把封面换成一眼可辨的标记图后气泡显示的正是标记图（排除了「读回失败但 video 又 seek 出同一帧」这个同形解释）。真因是那台 macOS 装的安装件是 08-09 构建的，四个封面符号 strings 零命中（正对照命中 1），比该功能落地早四天——那份 App 压根没有这个功能。所以本项一行代码没改，正确处置就是发出这一版。安卓侧本机与远端都没有 adb，如实标注未验证，没有写「应该也好了」。④ 桌面端更新进度条「0 到瞬间完成」的真因找到了，而且是用真 serde 1.0.228 独立 crate 实跑坐实的，不是照名字推断：enum 上写 rename_all 改的是变体名、写 rename_all_fields 改的才是变体内字段名，两者只差三个字母、编译期零告警。写成前者时 tag 被降成小写 started/progress/finished，而前端 switch 只认 Started/Progress/Finished ⇒ 一条都命不中、onProgress 一次都不调 ⇒ 进度条全程停在初值。旧的守卫只 grep 字段名，对这类格式漂移结构上不可能翻红，已删除并换成从源码派生真实线格式再比对的守卫，做过变异自证（同目录 8 个文件只红 1 个）。⑤ VPN 断开后那台设备要等心跳超时才恢复可选：判定式只认「此刻是不是本机在用」，而断开当帧本机隧道地址就没了，服务端那份 online 还是陈旧读数，于是本终端刚放开的设备被自己判成「已被其它终端占用」。改为「是否由本终端持有」，新增纯函数把「记住」与「忘掉」两条规则配成对——少掉「忘掉」那半条会让地址被永久放行、废掉死锁防护，变异自证正是删那半条（只红 3 条、另 18 条全绿）。⑥ 接上后端 2026-08-13 起不做兼容的契约变更：群文件预签名两个端点新增必填 related_id，App 侧两处请求体都没有它，后端一上线群文件预览会全面 400。改法不是沿 prop 链把群 ID 钻透四五个组件（每个口子都能漏、漏了的症状与没改一样：静默 400），而是收敛成唯一解析点，复用仓内既有真值源；独立预览窗是另一个 webview、拿不到该 store，群 ID 由主窗在跨窗 handoff 时解析后传入；取不到时抛错而不是静默发一个缺字段的请求。守卫钉在请求体字面量这一层，因为钉 interface 恰好防不住本仓踩过的「改了类型≠传了字段」。验证与如实披露：合并态下 typecheck 0、eslint --max-warnings 0 通过、vitest 313 个文件 3393 条全过，且测试数目可逐笔追溯（311/3378 → 312/3385 → 313/3393），没有任何测试在合并过程中消失或被削弱——「绿」本身不构成证据，这条才是。三条未验证项如实标注、不写成已验收：② 的「逐像素同形」无真机像素证据（另有两条结构性差异：视频缩略图在解析本地封面那几毫秒返回 null 会让完成切换那一帧短暂空白；秒传极小文件时尺寸回填可能晚于条目离队），④ 的进度条无真机证据（只有静态与 jsdom 两层），③ 的安卓侧零证据。另报一条只报不改的存量缺陷：.github/workflows/test.yml 的 paths 前缀在仓内零命中（正对照 3），该 workflow 结构上永不触发，所以本版新增的守卫有效、但它的 CI 那条腿是死的，不能说成「CI 会拦」。
